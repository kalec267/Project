관리자 전용 도서 등록

BookController에서 관리자 권한을 확인한 뒤 등록 화면을 제공하고, 입력된 도서 정보를 Service와 DAO 계층을 통해 저장하도록 구현했습니다. ISBN을 이용한 도서 정보 자동 조회 기능도 등록 화면과 연동했습니다.

고객 문의 게시판

CsController를 중심으로 문의 등록·조회·수정·삭제를 처리하고, 관리자가 답변을 작성하면 상태가 ‘답변대기’에서 ‘답변완료’로 변경되도록 구성했습니다.

Spring Security와 BCrypt

CustomUserDetailsService와 권한 규칙을 연결하고, 회원가입 시 평문 비밀번호를 BCryptPasswordEncoder로 해시한 후 데이터베이스에 저장하도록 구현했습니다.

카카오 로그인과 세션 통합

인가 코드로 Access Token을 발급받아 사용자 정보를 조회하고, 신규 회원 저장 후 Spring Security 인증 객체와 loginUser 세션을 구성해 일반 로그인과 같은 사용자 흐름으로 연결했습니다.

이메일 인증 회원가입

인증번호 생성·메일 발송·일치 여부 검증 결과를 EMAIL_AUTH에 기록하고, 인증이 완료된 이메일만 회원가입을 진행할 수 있도록 프론트엔드와 백엔드를 연동했습니다.

01 · PROJECT OVERVIEW

프로젝트 개요

SWEETSCOOP은 고객용 무인 키오스크, 지점 운영 POS, 본사 총괄 백오피스를 하나의 서비스 흐름으로 연결하는 아이스크림 프랜차이즈 통합 플랫폼입니다.

LEVEL 1 · CLIENT

고객용 무인 키오스크

유연한 맛 선택 메커니즘을 반영한 직관적인 UI/UX. 프린터 하드웨어 통신 및 실시간 품절 처리(DB Lock 연동)가 구현된 POS 단말기입니다.

LEVEL 2 · BRANCH

지점별 매장 운영

지점장 전용 대시보드로 실시간 당일 매출 조회, 재고 추적, 본사 발주 승인 상태 확인이 가능합니다. 키오스크 영업 시작/중단 제어를 원격으로 처리합니다.

LEVEL 3 · HEADQUARTERS

본사 총괄 백오피스

가맹점의 통합 주문 데이터 적재, 신규 지점 운영 제어, 본사 물류창고 입출고 정보 및 발주 승인 흐름을 관장하는 핵심 코어입니다.

11 · SECURITY HARDENING
OWASP A07

인증 및 식별 실패 대응

1차 프로젝트의 관리자 로그인 API를 대상으로 자동화 반복 대입 가능성을 분석하고, 프론트엔드와 백엔드에 Turnstile 검증 절차를 추가했습니다.

보안 적용 전

1. 브라우저 로그인 화면을 거치지 않고 api 직접 호출가능 (자동화 도구를 통한 반복 대입 문제)

2. 잘못된 비밀번호는 HTTP 401이지만 요청 자체는 계속 처리됨 (계정 존재 여부 추측 가능)

보안 적용 후

1. 프론트엔드에서 Cloudflare Turnstile 인증 token 발급 및 백엔드에서 Cloudflare Siteverify API를 통한 재검증

2. Token 누락·만료·위조·검증 실패 시 HTTP 403으로 차단하고 일반 로그인 실패는 HTTP 401을 반환

취약점 발생 부분

Turnstile 적용 전에는 POST /api/admin/auth/login을 직접 호출하여 여러 비밀번호 후보를 반복 전송할 수 있었습니다.

발생 원인

로그인 요청이 정상 사용자 브라우저에서 수행되었는지 확인하는 별도의 보안 인증 Token 검증 단계가 없었습니다.

개선 방법

Token의 유효성을 백엔드에서 재검증하고 검증에 성공한 요청만 아이디·비밀번호 인증 단계로 전달했습니다.

보안 적용 전 · LoginController.java
// 모든 요청이 바로 자격 증명 검사로 진행
loginresponse response =
    authservice.authenticate(request);

return response.issuccess()
    ? responseentity.ok(response)
    : responseentity
        .status(httpstatus.unauthorized)
        .body("아이디 또는 비밀번호가 올바르지 않습니다.");

        );
    }
}

DB

MySQL Docker 환경에서 한글 데이터 깨짐

문제·대응

Docker MySQL을 사용하면서 한글 데이터가 깨지는 문제를 점검했습니다. DB·커넥션의 문자셋과 정렬 규칙을 일관되게 맞추고, 컨테이너 환경 변수와 기존 볼륨의 설정 영향을 확인하는 방식으로 접근했습니다.

배운 점

문자셋은 애플리케이션 한 곳만 바꿔서는 해결되지 않을 수 있으므로 DB·JDBC·컨테이너 설정을 함께 확인해야 한다는 점을 배웠습니다.

Backend

MyBatis Mapper 인식 오류

문제·대응

Mapper XML이 로드되지 않거나 인터페이스와 연결되지 않는 문제를 경험했습니다. mapper-locations, namespace, 인터페이스 패키지 스캔, XML statement id와 메서드명의 일치 여부를 단계별로 확인했습니다.

배운 점

프레임워크 오류는 코드 로직보다 설정·경로·이름 매핑 문제에서 발생하는 경우가 많아 설정값을 먼저 검증하는 습관을 갖게 되었습니다.

Frontend ↔ Backend

Vue–Spring Boot CORS 및 Proxy

문제·대응

Vue 개발 서버와 Spring Boot가 서로 다른 포트에서 실행되면서 API 요청의 Origin과 경로 문제가 발생했습니다. 개발 환경에서는 Vite Proxy로 /api 요청을 백엔드로 전달하고, 배포 환경에서는 Nginx Reverse Proxy로 경로를 통합했습니다.

배운 점

CORS를 무조건 허용하기보다 개발·운영 환경의 요청 경로를 명확하게 설계하는 것이 중요하다는 점을 배웠습니다.

카테고리와 메뉴 데이터를 API로 받아 화면에 표시하고 선택 결과를 다음 주문 단계로 전달하는 로직을 점검했습니다. 비동기 데이터 로딩 시점과 렌더링, 선택 상태 유지가 주요 확인 대상이었습니다.

배운 점

Vue에서는 데이터 변경과 DOM 렌더링 시점이 다를 수 있으므로 비동기 처리와 상태 변경 순서를 명확하게 이해해야 한다는 점을 배웠습니다.

Quality

SpotBugs Spring Endpoint 경고 분석

문제·대응

Controller의 RequestMapping 계열 메서드가 외부에서 접근 가능한 엔드포인트임을 알리는 SPRING_ENDPOINT 경고를 검토했습니다. 경고 자체를 즉시 취약점으로 단정하지 않고 인증·인가, 입력 검증, 노출 필요성을 기준으로 실제 위험을 확인했습니다.

배운 점

정적 분석 도구의 결과는 ‘수정할 오류 목록’이 아니라 위험을 검토하기 위한 신호이며, 코드의 실제 실행 맥락을 함께 봐야 한다는 점을 배웠습니다.

Security

Cloudflare Turnstile + k6 로그인 보안 검증

문제·대응

초기 로그인 API는 Turnstile Token 없이도 성공 요청이 가능한 상태를 테스트로 확인했습니다. Vue에서 발급받은 Token을 로그인 요청에 포함하고 Spring Boot가 서버 측 검증을 수행하도록 개선했습니다. 이후 k6로 Token 누락·불일치 요청이 HTTP 403으로 차단되는 것을 재검증했습니다.

배운 점

보안 기능은 ‘적용했다’는 사실보다 우회 요청을 직접 만들어 적용 전·후 결과를 비교해 검증하는 과정이 중요하다는 점을 배웠습니다.
